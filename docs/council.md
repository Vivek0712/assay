# Review council

## Seats

### aws advocate

_To ensure content remains valuable and correct over time, emphasizing practical execution and depth of solution._

**Must measure:** Practical execution of the solution; Depth of the engineering solution; Relevance and longevity of the content; Evidence of real-world application

**Evidence that counts:** Runnable code blocks; Linked GitHub repositories; Detailed explanation of the solution; Demonstration of the solution in action

**Gaps in the current rubric:** Undervalues practical application; Undervalues depth of engineering solution; Does not consider longevity and relevance

**Overweighted today:** Evidence of execution (terminal output)

### aws hero

_The current rubric fails to capture the true depth and originality of the work, focusing instead on superficial evidence of execution._

**Must measure:** System architecture complexity; Engineering challenges overcome; Novelty of the solution; Integration of different Python versions and ROS distributions; Safety mechanisms implemented

**Evidence that counts:** Detailed system architecture diagrams; Explanation of engineering challenges and solutions; Unique features of the system not seen elsewhere; Configuration files and registry entries for different robots; Safety mechanism code snippets

**Gaps in the current rubric:** Undervalues complexity and innovation of the system; Overemphasizes pasted terminal output as evidence of execution

**Overweighted today:** Pasted terminal output as evidence of execution

### practitioner

_A working cloud engineer needs to know if the solution is practical, reproducible, and cost-effective. The current rubric does not sufficiently emphasize these critical factors._

**Must measure:** Reproducibility of the solution; Functionality of the code; Documentation of gotchas; Cost implications

**Evidence that counts:** Step-by-step reproduction guide; Runnable code examples; Detailed documentation of potential issues; Cost breakdown of services used

**Gaps in the current rubric:** Undervalues practicality and reproducibility; Lacks emphasis on cost implications

**Overweighted today:** Originality

### learner

_To ensure the scoring system values content that is not only technically sound but also accessible and explanatory, which is crucial for learners at the user's stage._

**Must measure:** followability; depth of explanation; clarity of author's reasoning

**Evidence that counts:** clear explanations; logical flow; diagrams; step-by-step instructions; detailed comments in the code

**Gaps in the current rubric:** followability; depth of explanation; clarity of author's reasoning

**Overweighted today:** technical details like code substance and source integrity

## Proposed pillars

| weight | pillar | measures |
|---|---|---|
| 30 | Practical Execution | Evidence of the solution being runnable and functional |
| 20 | Depth of Solution | Complexity and innovation of the system |
| 15 | Reproducibility | Ability to reproduce the solution |
| 10 | Cost Implications | Cost-effectiveness of the solution |
| 15 | Followability | Clarity and accessibility of the content |

**Total: 90**

### Evidence each pillar accepts

- **Practical Execution** — Runnable code blocks; Linked GitHub repositories; Detailed explanation of the solution; Demonstration of the solution in action
- **Depth of Solution** — Detailed system architecture diagrams; Explanation of engineering challenges and solutions; Unique features of the system
- **Reproducibility** — Step-by-step reproduction guide; Runnable code examples; Detailed documentation of potential issues
- **Cost Implications** — Cost breakdown of services used
- **Followability** — Clear explanations; Logical flow; Diagrams; Step-by-step instructions; Detailed comments in the code

### Key change

The key change is broadening what counts as evidence of execution to include runnable code blocks, linked GitHub repositories, detailed explanations, and demonstrations, rather than relying solely on terminal output.

### Where the seats disagreed

The constituencies conflicted on the weight of evidence of execution and the importance of originality. The revised rubric broadens what counts as evidence of execution and reduces the weight of originality to balance the rubric.

### Kept unchanged

- The principle that a claim of having done something must be backed by an artefact.
